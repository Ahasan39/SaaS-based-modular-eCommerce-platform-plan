System Architecture & Panel Overview
Four user types, one unified backend
🔴 Super Admin Panel
Platform Owner
  • Manage all website-subscription customers (tenants)
  • Create & configure feature packages (Free / Premium)
  • Assign/revoke premium features per tenant
  • Global platform settings & license management
  • Revenue dashboard (subscriptions, renewals)
  • Manage all admins and their permissions
  • System-wide analytics & health monitoring
  • Update/deployment management
🔵 Admin Panel (Tenant Admin)
Store Owner / Manager
  • Full product & category management
  • Order processing & fulfilment
  • Inventory management & low-stock alerts
  • Customer management & reviews
  • Marketing: coupons, campaigns, banners
  • Shipping & courier integration
  • Reports & analytics dashboard
  • Only sees features unlocked by Super Admin
🟣 Website Subscription Customer
Paying SaaS Tenant
  • Gets an isolated e-commerce storefront
  • Access only to features they subscribed for
  • Basic features free; premium features unlocked on payment
  • Self-service settings: theme, branding, domain
  • Their own customers (Normal Customers) shop here
  • Billing & subscription management portal
  • Feature request & upgrade flow
🟢 Normal Customer (End Shopper)
End User / Shopper
  • Browses & shops on a tenant's storefront
  • Registration, login, social login
  • Cart, checkout, order tracking
  • Wishlist, reviews, recently viewed
  • Address book & profile management
  • Access only to features the tenant has unlocked
  • Payment via COD, bKash, Shurjopay, etc.
🔓
Open-Source + Freemium Feature Model
What's free, what's locked, how the business model works
✅ Free / Open-Source Core

Anyone can clone, deploy, and use these without paying:

  • Product catalog (unlimited products)
  • 3-level category & brand management
  • Basic order management (CRUD)
  • Customer registration & login (JWT)
  • Shopping cart & basic checkout
  • Cash on delivery payment
  • Basic admin dashboard
  • REST API (core endpoints)
  • Basic SEO & meta tags
  • Contact form & custom pages
🔒 Premium (Paid / Unlockable)

Website subscription customers unlock these based on their chosen plan:

  • Multi-payment gateways (bKash, Shurjopay)
  • Courier API integration (Pathao, Steadfast)
  • Advanced analytics & reports
  • Email/SMS notifications
  • Abandoned cart recovery
  • Social login (Google, Facebook)
  • Bulk product import/export
  • Campaign & coupon management
  • Pixel integrations (FB, TikTok, GA)
  • Multi-warehouse & supplier mgmt
  • WhatsApp notifications
  • Advanced inventory (stock history)
  • Product comparison & wishlists
  • Custom theme & branding
⚙️ Feature Toggle Mechanism

The feature_toggles table (already in schema) acts as the feature gate. Super Admin sets which features are enabled per tenant. The API endpoint /api/v1/feature-toggles serves the active feature list to the React frontend, which shows/hides UI accordingly. No code changes needed — pure database-driven toggle system.

Hosting Recommendations
Best options for a Laravel + React + MySQL stack at scale
⭐ Best Choice
DigitalOcean
From $24/mo (4GB droplet) · Managed DB extra
  • Managed MySQL database (automated backups)
  • Managed Redis for queues & caching
  • Object Storage (Spaces) for media files
  • App Platform for zero-downtime deploys
  • Simple, predictable pricing
  • Laravel-friendly Nginx stacks
  • Great for multi-tenant SaaS
⭐ Best for Scale
AWS (EC2 + RDS)
From $40–80/mo (t3.medium + RDS)
  • RDS MySQL with read replicas for scale
  • ElastiCache (Redis) managed service
  • S3 + CloudFront CDN for media
  • Elastic Load Balancer for traffic spikes
  • Auto-scaling groups
  • SES for transactional emails
  • Best for high-growth, multi-tenant SaaS
Vultr / Hetzner
From $12–20/mo · Budget-friendly
  • Good performance per dollar
  • SSD VPS with full root access
  • Managed DB add-ons available
  • Object storage for media
  • Manual server management required
  • Good for initial launch / MVP
  • Hetzner excellent for EU/Asia regions

Key project risks and how to handle them

Definition of Done & Agile Ceremonies
Quality gates and team rituals

Definition of Done (per story)

  • Code reviewed by at least 1 other developer
  • Unit/feature tests written and passing
  • API endpoint documented in Postman collection
  • No critical Laravel debugbar SQL warnings
  • Feature toggle respected (premium features gated)
  • Responsive on mobile (375px) and desktop (1280px)
  • Merged to main branch via Pull Request

Agile Ceremonies

  • Daily Standup: 15 min — What did I do? What will I do? Blockers?
  • Sprint Planning: Day 1 of each sprint — pick stories from backlog
  • Sprint Review: Day 10 — demo working software to stakeholder
  • Retrospective: Day 10 — What went well? What to improve?
  • Backlog Grooming: Mid-sprint — refine upcoming stories
  • Tools: GitHub Projects (Kanban), Slack/Discord for communication
